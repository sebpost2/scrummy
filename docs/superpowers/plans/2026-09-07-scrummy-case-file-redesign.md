# Scrummy "Case File" Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-skin scrummy's existing design system into a distinctive "case file" identity (two-ink stamp palette, sharp data-card corners, structural mono type) and fix mobile navigation/board gaps found in the design audit.

**Architecture:** Token-driven CSS pass on `app/globals.css` (plain CSS custom properties, no Tailwind/CSS Modules) plus small, targeted markup changes only where the mobile nav and card-tab motif genuinely need new elements (`Nav.tsx` gets a new `MobileNavBar`, `BoardCard.tsx` gets a mono id). One new font (`IBM Plex Serif`, same family already used) wired through `layout.tsx`. No new npm dependencies, no data model or server-action changes.

**Tech Stack:** Next.js 16 (App Router), React 19, TypeScript strict, `next/font/google`, Vitest + `react-dom/server` for page tests.

**Spec:** `docs/superpowers/specs/2026-09-07-scrummy-case-file-redesign-design.md`

## Global Constraints

- **Next.js 16 is not the version in your training data.** Before touching `app/layout.tsx` or any App Router file, check `node_modules/next/dist/docs/` if anything here doesn't match expectations. The `<!-- BEGIN:nextjs-agent-rules -->` block in `AGENTS.md` is regenerated by `next dev` — commit it if it appears in the diff.
- **No data model changes.** `prisma/schema.prisma` is frozen. `BoardTask.id` stays the existing cuid — the "mono id" on cards is derived client-side (`id.slice(-4)`), not a new field.
- **No server mutation logic changes.** Nothing in `lib/**/mutations.ts` or `app/**/actions.ts` changes.
- **No new npm dependencies.** `lucide-react` (icons) and `next/font/google` (fonts) are already installed/integrated — reuse them.
- **Preserve asserted copy.** These exact strings are asserted by tests and must remain in rendered output: `"To do"`, `"In progress"`, `"Done"`, `"Nothing assigned"`, `"No projects yet"`, `"changed the priority"`, `"created this task"`, `"commented"`. This plan does not change any of them.
- **Theme selector contract:** light palette on bare `:root`; dark overrides duplicated under BOTH `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { … } }` AND `:root[data-theme="dark"] { … }`. Never define a color only inside a media/attribute block. `body` always has an explicit `background: var(--bg)`.
- **Motion:** every new transition/animation must be disabled under `@media (prefers-reduced-motion: reduce)` (an existing global rule already does `* { transition: none !important; }` under that query — new `@keyframes` animations still need their own opt-out, same pattern as `.skeleton`).
- **Path alias:** `@/*` → repo root.
- **Verification per task:** `npm run lint` and `npm test` both pass before every commit. If `npm test` can't reach its Postgres (`.env.test`), say so and stop rather than skipping.
- **Commit style:** short imperative subject. End every commit message with:
  `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`
